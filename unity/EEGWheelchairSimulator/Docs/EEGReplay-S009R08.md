# S009 Run 08: 기록 시각에 맞춘 EEG → Unity 재생

검증일: 2026-11-16. `unity-eeg-inference-demo`의 저장 EEG 재생 검증 기록입니다.

## 입력과 확정된 조건

- `S009R08_eeg.npy`: float32, `(149, 9, 320)`, 유한값 확인. 160 Hz의 2초 윈도입니다.
- `S009R08_windows.csv`: 149개 행, `EEG_Index` 0–148. 정답은 Rest 60개, Left 51개, Right 38개입니다.
- `S009R08_trial_onsets.csv`: 28개 Trial의 녹음 시작 기준 초·샘플 인덱스. 모든 행에서 `초 × 160 = 샘플 인덱스`가 일치합니다.
- 팀원이 확인한 채널 순서: `FC3, FCz, FC4, C3, Cz, C4, CP3, CPz, CP4`.
- 팀원이 확인한 클래스: `0=Left`, `1=Right`, `-1=Rest`. NPY 자체에는 채널 이름 메타데이터가 없습니다.
- Trial 2·16은 휴식 구간이지만 품질 검사에서 모든 윈도가 제외됐습니다. 두 CSV에 해당 행이 없어도 이후 Trial의 절대 시작 시각으로 공백을 보존합니다.
- 세 입력 파일은 별도 전달받은 로컬 데이터이며 이 작업에서 저장소에 추가하지 않았습니다.

## 재생 방식

```powershell
python unity/EEGWheelchairSimulator/Tools/PythonTestSender/send_eeg_predictions.py --windows-csv '<S009R08_windows.csv 경로>' --trial-onsets-csv '<S009R08_trial_onsets.csv 경로>' -- --input '<S009R08_eeg.npy 경로>' --model eegnet --threshold 0.90
```

Unity에서 B1 장면을 열고 Play → Control Source **Python** → **START**로 수신을 시작합니다. 기본 포트는 `127.0.0.1:5055`입니다.

1. 기존 `predict.py`로 149개 윈도를 추론합니다. 기본 경로의 학습 평균·표준편차와 EEGNet 체크포인트를 사용합니다. 표준화된 입력에만 `--standardized`를 지정합니다.
2. `Trial`로 시간표와 윈도를 연결합니다. 예측 적용 시각은 `Onset_sample_from_run_start / 160 + End_sec_from_event`입니다.
3. 모든 추론이 끝난 뒤 재생 시계의 0초를 녹음 시작으로 맞춥니다. 첫 예측인 2.50초까지 `STOP`입니다.
4. `Left → LEFT`, `Right → RIGHT`, `Hold → STOP`. 기본값에서 각 예측은 최대 0.25초 동안 적용합니다. 다음 유효 예측이 없으면 `STOP`을 보내고 다음 절대 시각까지 기다립니다. CSV의 정답 라벨로 명령을 덮어쓰지 않습니다.
5. 마지막 예측은 122.90초, 최종 `STOP`은 123.15초입니다. Unity가 마지막 패킷을 처리하도록 0.25초 기다린 뒤 연결을 닫습니다. 연결 종료 후에도 정지합니다.

예측을 기다리는 구간은 7.35–15.30초와 65.75–72.20초에 각각 7.95초, 6.45초입니다. 이 구간에는 제외된 Trial 2·16뿐 아니라 앞선 명령 만료 후의 시간과 다음 윈도 수집 시간도 포함됩니다. 이 전체 대기 시간을 해당 휴식 Trial 자체의 길이로 해석하면 안 됩니다.

원본 녹음 종료 시각은 제공되지 않아 마지막 명령 이후 녹음의 나머지 길이는 알 수 없습니다. 이것은 **저장 EEG의 시간축 재생**이며 실시간 수집·전처리·온라인 추론 지연을 검증한 것은 아닙니다. `--trial-onsets-csv`를 생략하면 기존의 압축 구간 재생을 사용합니다.

## EEGNet, threshold 0.90 결과

| 정답 구간 | Left 예측 | Hold 예측 | Right 예측 | 합계 |
|---|---:|---:|---:|---:|
| Rest | 0 | 58 | 2 | 60 |
| Left | 0 | 46 | 5 | 51 |
| Right | 0 | 34 | 4 | 38 |
| 합계 | 0 | 138 | 11 | 149 |

팀원의 독립 확인 결과와 일치합니다. 휴식 2개와 왼쪽 5개에서 우회전 명령이 잘못 나오고, 실제 오른쪽 구간에서는 4개가 우회전으로 통과합니다. `Hold`는 휴식을 학습한 세 번째 클래스가 아니라 좌·우 예측 확률이 기준값 미만일 때 보류한 결과입니다.

휴식 윈도 기준 회전 오명령 비율은 2/60 = 3.33%입니다. 윈도가 겹치므로 이 수치는 독립 시행의 오명령률이나 시간당 오명령률을 뜻하지 않습니다. 이 한 Run의 결과를 전체 테스트 정확도로 일반화하지 않습니다. 채널·클래스 순서가 확인된 상태에서도 좌회전 명령은 통과하지 않았으므로 모델 팀은 좌·우 점수 분포, 휴식 억제, 기준값별 명령 통과율과 반대 방향 오류를 함께 검토해야 합니다. 이 데이터를 보고 기준값을 맞춘 뒤 같은 데이터로 성능을 입증하지 말고 별도 평가 데이터로 확인해야 합니다.

## 검증 결과

- Python 시간표 회귀 테스트 7개 통과: 누락 Trial과 같은 Trial 내부 누락 윈도 정지, 잘못된 시간표·윈도 순서 거부, 기존 3개 샘플 모드, 송신 처리 시간의 누적 지연 방지.
- 실제 149개 윈도의 예측 적용 시각을 정수 샘플 인덱스로 별도 계산해 모두 일치하는지 확인했습니다.
- Unity 6000.3.24f1의 별도 검증 프로젝트에서 B1 장면을 Play 모드로 실행하고 실제 모델 추론 → TCP → 휠체어 동작을 확인했습니다. 178개 패킷(149개 모델 결과 + 29개 시간 제어 STOP)을 순서대로 수신했습니다. RIGHT 11개, STOP 167개였습니다.
- 두 긴 대기 구간에서 STOP, 최종 STOP 시각 123.140초(예정 123.150초), 연결 종료 후 정지를 확인했습니다. STOP 상태 회전량 0.00도, 위치 이동 없음. RIGHT 상태 회전도 확인했습니다. 렌더링 프레임에 따라 회전량과 수신 시각에 작은 차이가 생길 수 있습니다.
- 검증 로그에는 기존 Unity Editor 검색 인덱스의 `SearchInit.IndexationOnStartup` 예외가 1회 있습니다. 이후 Play 모드 및 EEG 동작 검증은 통과했습니다. 검색 인덱스 문제는 이번 변경에서 수정하지 않았습니다.
